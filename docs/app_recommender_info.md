# 🗣️ Приложение Recommender

Приложение реализует алгоритмы рекомендаций для e-commerce:

- Алгоритм ***PageRank*** для оценки важности узлов (товаров).
- Алгоритм ***Collaborative Filtering*** (коллаборативная фильтрация) для рекомендаций на основе схожести пользователей.
- Алгоритм нахождения ближайших соседей (***k-Nearest Neighbors***) для нахождения пользователей с похожими интересами.

---

## 📘 Архитектура графа для *PageRank*

### 1. Узлы графа
- Пользователи (`user_{id}`)
- Продукты (`product_{id}`)
- Категории (aisle) (`aisle_{id}`)

### 2. Ребра графа
**a) Пользователь -> Продукт**  
- Источник: `UserInteraction`, где заполнен `product_id`.  
- Вес = `weight` (2 для implicit, 5 для explicit).  
- Пример: `user_11 → product_2001 (weight=2)`

**b) Пользователь -> Категория**  
- Источник: `UserInteraction`, где `interaction_type=preference` и заполнен `aisle_id`.  
- Вес = `weight` (например, 5).  
- Пример: `user_11 → aisle_1 (weight=5)`

**c) Категория -> Продукты**  
- Источник: связь "продукт принадлежит категории" (из таблицы продуктов).  
- Вес = понижающий коэффициент (например, 0.5).  
- Пример: `aisle_1 → product_2001 (weight=0.5)`

### 3. Общая структура графа

Пример для `user_11`:
```bash
user_11
│
├──> product_2001 (weight=2)       # implicit - неявные связи (из истории заказов)
│
├──> aisle_1 (weight=5)            # explicit - явные предпочтения на странице "Мои предпочтения"
│
├──> product_2002 (weight=0.5)     # explicit - продукты в предпочитаемой категории
├──> product_2003 (weight=0.5)     # explicit - продукты в предпочитаемой категории
└──> product_2004 (weight=0.5)     # explicit - продукты в предпочитаемой категории
```

---

### 4. Алгоритм построения графа
1. Создаем пустой граф `nx.DiGraph()`.  
2. Добавляем вершины пользователей, продуктов, категорий.  
3. Добавляем ребра:
    - `user → product` (из UserInteraction с `product_id`)  
    - `user → aisle` (из UserInteraction с `aisle_id`)  
    - `aisle → product` (из справочника продуктов)  
4. Запускаем `nx.pagerank(G, alpha=0.85, weight="weight")`.  
5. Извлекаем топ-N продуктов по PageRank.

### 5. Логика весов
- Явное предпочтение продукта - самое сильное (5).  
- Неявное взаимодействие с продуктом (история заказов) - среднее (2).  
- Выбор категории (aisle) - сильное (5), но далее ослабляется при переходе к продуктам (0.5).  

Таким образом:
- если пользователь любит категорию "Молочные продукты", то йогурт/сыр/и т.д. получат "boost" в 0.5,  
- если пользователь явно отметил продукт, то этот продукт будет в топе (5),  
- implicit (повторные заказы) будут учитываться (2), но слабее, чем явные предпочтения.

### 6. Преимущества
- Мы учитываем **и продукты, и категории**.  
- Избегаем размазывания весов по сотням товаров при выборе категории.  
- PageRank будет работать естественно: важные категории подтянут связанные продукты.
