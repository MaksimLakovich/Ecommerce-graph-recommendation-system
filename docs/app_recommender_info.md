# 🗣️ Приложение Recommender

Приложение реализует алгоритмы рекомендаций для e-commerce:

- Алгоритм ***PageRank*** для оценки важности узлов (товаров).
- Алгоритм ***Collaborative Filtering*** (коллаборативная фильтрация) для рекомендаций на основе схожести пользователей.
- Алгоритм нахождения ближайших соседей (***k-Nearest Neighbors***) для нахождения пользователей с похожими интересами.

---

## ⚙️ Архитектура графа для алгоритма *PageRank*

### 1. Вершины (узлы) графа
- Пользователи (`user_{id}`)
- Продукты (`product_{id}`)
- Категории (aisle) (`aisle_{id}`)

### 2. Ребра графа
**a) Пользователь -> Продукт**  
- Источник: `UserInteraction`, где заполнен `product_id`.  
- Вес = `weight` (2 для implicit, 5 для explicit).  
- Пример: `user_11 → product_2001 (weight=2)`

**b) Пользователь -> Категория**  
- Источник: `UserInteraction`, где `interaction_type=preference` и заполнен `aisle_id`.  
- Вес = `weight` (например, 5).  
- Пример: `user_11 → aisle_1 (weight=5)`

**c) Категория -> Продукты**  
- Источник: связь "продукт принадлежит категории" (из таблицы продуктов).  
- Вес = понижающий коэффициент (например, 0.5).  
- Пример: `aisle_1 → product_2001 (weight=0.5)`

### 3. Общая структура графа

Пример для `user_11`:
```bash
user_11
│
├──> product_2001 (weight=2)       # implicit - неявные связи (из истории заказов)
│
├──> aisle_1 (weight=5)            # explicit - явные предпочтения на странице "Мои предпочтения"
│
├──> product_2002 (weight=0.5)     # explicit - продукты в предпочитаемой категории
├──> product_2003 (weight=0.5)     # explicit - продукты в предпочитаемой категории
└──> product_2004 (weight=0.5)     # explicit - продукты в предпочитаемой категории
```

### 4. Алгоритм построения графа
1. Создаем пустой граф `nx.DiGraph()`.  
2. Добавляем вершины пользователей, продуктов, категорий.  
3. Добавляем ребра:
    - `user → product` (из UserInteraction с `product_id`)  
    - `user → aisle` (из UserInteraction с `aisle_id`)  
    - `aisle → product` (из справочника продуктов)  
4. Запускаем `nx.pagerank(G, alpha=0.85, weight="weight")`.  
5. Извлекаем топ-N продуктов по PageRank.

### 5. Логика весов
- Явное предпочтение продукта - самое сильное (5).  
- Неявное взаимодействие с продуктом (история заказов) - среднее (2).  
- Выбор категории (aisle) - сильное (5), но далее ослабляется при переходе к продуктам (0.5).  

Таким образом:
- если пользователь любит категорию "Молочные продукты", то йогурт/сыр/и т.д. получат "boost" в 0.5,  
- если пользователь явно отметил продукт, то этот продукт будет в топе (5),  
- implicit (повторные заказы) будут учитываться (2), но слабее, чем явные предпочтения.

### 6. Преимущества
- Мы учитываем **и продукты, и категории**.  
- Избегаем размазывания весов по сотням товаров при выборе категории.  
- PageRank будет работать естественно: важные категории подтянут связанные продукты.

## ⚙️ Архитектура графа для алгоритма *Collaborative Filtering*

### 1. Вершины (узлы) графа

- Пользователи (`user_{id}`)
- Продукты (`product_{id}`)
- Категории (aisle) (`aisle_{id}`)

### 2. Ребра графа

**a) Пользователь -> Продукт**  
- Источник: `UserInteraction`, где заполнен `product_id`.  
- Вес = `weight` (2 для implicit, 5 для explicit).  
- Пример: `user_42 — product_3571 (weight=2)`

**b) Пользователь -> Категория**  
- Источник: `UserInteraction`, где `interaction_type=preference` и заполнен `aisle_id`.  
- Вес = `weight` (например, 5).  
- Пример: `user_42 — aisle_37 (weight=5)`

**c) Категория -> Продукты**  
- Источник: связь "продукт принадлежит категории" (из таблицы продуктов).  
- Вес = понижающий коэффициент (например, 0.5).  
- Пример: `aisle_37 → product_3002 (weight=0.5)`

### 3. Общая структура графа

Пример для user_42:
```bash
user_42
│
├── product_3571 (weight=2)       # implicit — история заказов
│
├── aisle_37 (weight=5)           # explicit — явное предпочтение категории
│
├── product_3002 (weight=0.5)     # boost из предпочитаемой категории
├── product_3003 (weight=0.5)     # boost из предпочитаемой категории
└── product_3004 (weight=0.5)     # boost из предпочитаемой категории
```

### 4. Алгоритм построения графа

1. Создаем пустой ненаправленный граф `nx.Graph()` (так как CF - симметричная модель). 
2. Добавляем вершины: пользователи, продукты, категории. 
3. Добавляем ребра:
    - `user → product` (из UserInteraction с `product_id`)  
    - `user → aisle` (из UserInteraction с `aisle_id`)  
    - `aisle → product` (из справочника продуктов)

### 5. Логика вычислений

1. Для заданного пользователя считаем схожесть с другими пользователями:
   - используем **коэффициент Жаккара**
   - `similarity(user1, user2)` = `|общие соседи|` / `|все соседи|`
   - соседи = продукты и категории, связанные с пользователем

2. На основе схожих пользователей собираем кандидаты-продукты:
   - если похожий пользователь имеет продукт, которого ещё нет у текущего, то этот продукт становится кандидатом 
   - вес кандидата = сумма схожестей по всем похожим пользователям

3. Сортируем продукты-кандидаты по убыванию суммарного веса.

4. Возвращаем top-N рекомендаций.

### 6. Логика весов

- Явное предпочтение продукта - самое сильное (5).  
- Неявное взаимодействие с продуктом (история заказов) - среднее (2).  
- Выбор категории (aisle) - сильное (5), но далее ослабляется при переходе к продуктам (0.5).  

***Важно (!)***  
Веса учитываются в структуре графа, но для вычисления схожести (Жаккар) мы используем только факт связи (наличие узла). В будущем можно заменить на взвешенный Жаккар или косинусное сходство.

### 7. Преимущества

- Простая и понятная модель, которую легко объяснить бизнес-заказчику.
- Рекомендации основаны на реальном ***"похожем поведении"*** покупателей.
- Легко расширяется: можно добавить другие типы взаимодействий.

## ⚙️ Архитектура графа для алгоритма *k-Nearest Neighbors (kNN)*

### 1. Вершины (узлы) графа

- Пользователи (`user_{id}`)  
⚠️ В отличие от PageRank и CF, в графе kNN нет узлов продуктов и категорий — они учитываются только на этапе расчёта схожести между пользователями.

### 2. Ребра графа

**Пользователь -> Пользователь**

- Источник: вычисляется на основе общих продуктов и категорий из `UserInteraction`.
- Вес = коэффициент Жаккара.  
`Коэффициент Жаккара = "число общих (intersection_products)" / "число уникальных (union_products)"`
- Пример: `user_42 — user_77 (weight=0.67)`

### 3. Общая структура графа

Пример:

```bash
user_42
│
├── user_77 (weight=0.67)
├── user_15 (weight=0.5)
└── user_99 (weight=0.25)
```

### 4. Алгоритм построения графа

1. Создаем пустой ненаправленный граф `nx.Graph()`.
2. Добавляем вершины пользователей.
3. Для каждой пары пользователей вычисляем коэффициент Жаккара:

   * если результат > 0, создаем ребро `user1 - user2` с весом.

### 5. Логика вычислений

1. Для заданного пользователя находим `k` ближайших соседей:
   - сортируем всех соседей по весу (схожести).
   - выбираем top-k.


2. Собираем продукты ближайших соседей:
   - исключаем продукты, которые уже есть у текущего пользователя.
   - формируем список кандидатов.


3. Считаем рейтинг для каждого кандидата:
   - каждый сосед добавляет +1 к продукту.
   - можно доработать: учитывать вес схожести при подсчете.


4. Сортируем кандидатов и возвращаем top-N продуктов.

### 6. Преимущества

* Простая модель.
* Хорошо работает для нахождения "клубов по интересам" (групп пользователей).
* Может использоваться как вспомогательный алгоритм для гибридных моделей.
