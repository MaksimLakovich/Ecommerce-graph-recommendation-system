# 🎯 Приложение Preferences

Приложение `preferences` отвечает за хранение взаимодействий пользователей с продуктами (не явные предпочтения) и их явных предпочтений (что они сами указали в предпочтении).  
Используется для построения системы рекомендаций на основе графов.

---

## 🗂 Модели

### 1. UserInteraction
Хранит все взаимодействия пользователя с продуктами или категориями (aisle).  
События делятся на:
- **Explicit** — явные, указанные пользователем на странице "Ваши предпочтения".
- **Implicit** — неявные, извлеченные из истории заказов (purchase/reorder).

**Поля:**
- `user_id` — пользователь, сделавший действие (AppUser)
- `product_id` — продукт, с которым произошло взаимодействие (может быть Null для explicit-preference на уровне aisle)
- `aisle_id` — категория (aisle), с которой произошло взаимодействие (для явных предпочтений)
- `interaction_type` — тип события (`purchase`, `reorder`, `preference`)
- `source` — источник события (`implicit`, `explicit`)
- `weight` — вес события (используется при построении графа рекомендаций)

---

### 2. UserPreference
Явные предпочтения пользователя, выбранные на странице "Мои предпочтения".  
Используется для фильтрации и первичной настройки рекомендаций.

**Поля:**
- `user_id` — пользователь, сделавший выбор (AppUser)
- `product_id` — выбранный продукт (может быть Null)
- `aisle_id` — выбранная категория/aisle (может быть Null)

**Особенности:**
- Для каждого пользователя запрещено дублирование одинакового продукта или aisle (через UniqueConstraint).

---

## 🖥 Интерфейс

Реализована страница ***"Мои предпочтения"***:

- Пользователь видит список всех `aisle` в виде чекбоксов.  
- Можно выбрать любое количество значений (0 = ничего не выбрано).  
- Кнопка «Сохранить мои предпочтения» выполняет:
  1. Сохраняет выбранные значения в `UserPreference`.  
  2. Автоматически создает соответствующие записи в `UserInteraction` с типом `preference`, источником `explicit` и весом `5.0`.  
  3. При повторном сохранении старые записи удаляются и пересоздаются заново.  
- При повторном посещении страницы текущие предпочтения отображаются отмеченными в чекбоксах.  
- Список чекбоксов обернут в прокручиваемый блок.

## 🔄 Кэширование рекомендаций

- Для каждого пользователя рекомендации сохраняются в Redis-кэше для ускорения работы API.  
- TTL кэша по умолчанию - 1 час (`RECOMMENDER_CACHE_TTL = 3600`). Можно указать настройку в settings.py  
- Кэш используется для алгоритмов:
  - PageRank
  - Collaborative Filtering
  - kNN  

### Сброс кэша
- Сбрасывается автоматически при изменении записей `UserInteraction` покупателем (навая покупка или новые предпочтения).  
- Используется сигнал `post_save` в `preferences/signals.py`:
  ```python
  @receiver(post_save, sender=UserInteraction)
  def reset_cache_on_user_interaction(sender, instance, **kwargs):
      reset_recommendations_cache(instance.user_id_id)

1. Поскольку добавление явных предпочтений выполняется через полное удаление старых и запись новых данных, отдельный post_delete не требуется.

2. Любое изменение UserInteraction гарантированно сбрасывает кэш и обновляет рекомендации при следующем запросе.

---

## 🔗 Схема связи

`AppUser` → `UserInteraction` → `Product`  
→ UserInteraction → Aisle  
→ UserPreference → Product  
→ UserPreference → Aisle  


- Пользователь может иметь множество явных предпочтений.
- Взаимодействия фиксируются и для продуктов, и для категорий.
- Используется вес событий для учета важности при построении графов.

---

## 🖥 Админка

В админке доступны:
- Список взаимодействий (`UserInteraction`) с фильтрацией по типу события и источнику.
- Список явных предпочтений (`UserPreference`) с фильтрацией по пользователю.
- Возможность поиска по пользователю, продукту и aisle.
